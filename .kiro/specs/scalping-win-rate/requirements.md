# Requirements: Improve Scalping Strategy Win Rate to 60%+

## Introduction
The current scalping module achieves ~33% win rate on RELIANCE.NS using 1-minute delayed yfinance data. This spec covers all improvements needed to reach the 60-72% win rate target. The improvements focus on signal quality, market condition awareness, and risk management — all within the existing yfinance data infrastructure before real-time data integration.

---

## Requirements

### Requirement 1: Market Session Filter

**User Story:** As a trader, I want the bot to only trade during the highest-liquidity window so that signals are cleaner and win rate improves.

#### Acceptance Criteria
1. WHEN a signal is generated THEN the system SHALL check if current time is within 9:15 AM - 11:15 AM IST for NSE
2. WHEN current time is outside the trading window THEN the system SHALL reject the signal and not enter any trade
3. WHEN current time is within the last 15 minutes before market close (3:15-3:30 PM) THEN the system SHALL close all open positions
4. IF the symbol is a US stock THEN the system SHALL use 9:30 AM - 11:30 AM EST as the trading window
5. WHEN no trades are taken outside the window THEN the system SHALL log the reason as "outside_trading_window"

---

### Requirement 2: Volatility Regime Filter

**User Story:** As a trader, I want the bot to detect choppy/sideways markets and avoid trading in them so that false signals are reduced.

#### Acceptance Criteria
1. WHEN calculating a signal THEN the system SHALL compute the Average Directional Index (ADX) on the current data
2. IF ADX < 20 THEN the system SHALL classify the market as "choppy" and reject all signals
3. IF ADX >= 20 AND ADX < 40 THEN the system SHALL classify as "trending" and allow signals
4. IF ADX >= 40 THEN the system SHALL classify as "strong trend" and allow signals with higher confidence
5. WHEN ATR is below the 20-period average ATR THEN the system SHALL reduce position size by 50%
6. WHEN the market regime is logged THEN it SHALL include ADX value and regime classification

---

### Requirement 3: Ensemble Signal Scoring

**User Story:** As a trader, I want all three strategies to agree before entering a trade so that only high-confidence signals are taken.

#### Acceptance Criteria
1. WHEN evaluating a potential trade THEN the system SHALL run all three strategies (EMA, VWAP, RSI) simultaneously
2. WHEN calculating ensemble score THEN the system SHALL weight strategies: EMA 40%, VWAP 35%, RSI 25%
3. IF ensemble score >= 70 THEN the system SHALL generate a BUY or SELL signal
4. IF ensemble score < 70 THEN the system SHALL output HOLD and not enter any trade
5. WHEN at least 2 out of 3 strategies agree on direction THEN the system SHALL add a 10-point bonus to ensemble score
6. WHEN all 3 strategies agree THEN the system SHALL add a 20-point bonus to ensemble score
7. WHEN ensemble score is calculated THEN it SHALL be stored with each trade record for analysis

---

### Requirement 4: Adaptive Stop Loss

**User Story:** As a trader, I want stop losses to adapt to current market volatility so that trades are not stopped out prematurely in volatile conditions.

#### Acceptance Criteria
1. WHEN calculating stop loss THEN the system SHALL use ATR multiplied by a volatility factor
2. IF current ATR > 1.5x average ATR THEN the system SHALL use ATR * 2.5 as stop loss distance
3. IF current ATR <= 1.5x average ATR THEN the system SHALL use ATR * 2.0 as stop loss distance
4. WHEN stop loss distance is calculated THEN it SHALL never be less than 0.15% of entry price
5. WHEN stop loss distance is calculated THEN it SHALL never be more than 0.5% of entry price
6. WHEN take profit is set THEN it SHALL always be 3x the stop loss distance (1:3 risk-reward)

---

### Requirement 5: ML Signal Confirmation

**User Story:** As a trader, I want an ML model to confirm signals before entry so that low-probability setups are filtered out.

#### Acceptance Criteria
1. WHEN a signal is generated by ensemble scoring THEN the system SHALL pass features to an ML classifier
2. WHEN the ML classifier predicts THEN it SHALL output a probability score (0-1) for the signal direction
3. IF ML probability < 0.55 THEN the system SHALL reject the signal
4. IF ML probability >= 0.55 THEN the system SHALL allow the signal to proceed
5. WHEN training the ML model THEN it SHALL use the following features: RSI, MACD, EMA diff, volume ratio, ATR, ADX, VWAP distance, price momentum
6. WHEN the ML model is trained THEN it SHALL use at least 500 historical samples
7. WHEN ML model accuracy on test set is below 55% THEN the system SHALL disable ML filtering and log a warning

---

### Requirement 6: Performance Validation

**User Story:** As a developer, I want to validate the improved strategy on sufficient historical data so that results are statistically meaningful.

#### Acceptance Criteria
1. WHEN running validation THEN the system SHALL require minimum 100 trades (relaxed from 500 due to yfinance 7-day limit)
2. WHEN validation completes THEN the system SHALL report: win rate, profit factor, Sharpe ratio, max drawdown, avg daily return
3. IF win rate >= 60% THEN the system SHALL mark the strategy as "validated for paper trading"
4. IF win rate < 60% THEN the system SHALL output specific recommendations for further improvement
5. WHEN comparing strategies THEN the system SHALL run all 3 symbols: RELIANCE.NS, TCS.NS, HDFCBANK.NS
6. WHEN validation report is generated THEN it SHALL be saved to `data/scalping/validation_report.json`
